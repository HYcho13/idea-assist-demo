# Gemini 요청 속도 및 대기 안내 개선

## 변경

- 웹과 Android의 Gemini `generationConfig.thinkingConfig.thinkingLevel`을 `low`로 지정한다. 현재 모델 `gemini-3.8-flash`는 유지한다. 지원하지 않는 `minimal`, `thinkingBudget: 0` 옵션을 넣지 않는다.
- 최대 출력 토큰 4096과 JSON 스키마는 유지한다. 하드 한도를 낮춰 잘린 JSON을 유발하는 대신 제목·설명·단계·연결 설명을 간결하게 작성하도록 요청한다. 주제·조건·세 단어, 필수 필드, 서로 다른 세 실행 단계와 발전 검증은 유지한다.
- Android Gemini 요청에서는 불필요한 예시 본문을 빼고 간결한 출력 지침을 추가한다. 기기 내 모델의 예시와 기존 OpenAI 설정은 유지한다.
- 사용자 요청에 따라 경과 시간과 10초·30초 지연 안내를 제거하고, 웹과 Android에 스피닝 휠 하나로 대기 상태를 표시한다. 취소 버튼과 클라우드 비용 안내는 유지한다. 실제 처리 단계·진행률·남은 시간을 추측해서 표시하지 않는다.
- 웹은 기존 CSS 회전 키프레임을 재사용하고 화면 읽기 프로그램에 대기 상태를 제공한다. 동작 줄이기 설정에서는 회전을 멈춘다. Android는 중앙 정렬된 48dp 기본 indeterminate ProgressBar를 사용한다. 경과 시간용 타이머·콜백·세션 시작 시각은 제거한다.
- 실제 모델 다운로드 상태 안내와 요청 시간 초과 처리는 유지한다. 규칙 시연에 인위적인 지연을 넣지 않는다.

공식 근거: [Google Gemini thinking 설정](https://ai.google.dev/gemini-api/docs/generate-content/thinking#controlling-thinking). Gemini 3.8 Flash에서 `low`는 지연을 줄이는 설정이고 기본값은 `medium`이다. 출력 토큰 한도는 추론·응답의 하드 컷오프이므로 간단히 줄이는 방식은 피했다.

## 검증과 한계

- Node 자동 테스트 84개, 웹 빌드, Android APK 빌드·설치 통과.
- Android 에뮬레이터 코어 검증 19개 그룹 통과. 기존 보관함 파일은 검증 전후 해시 동일.
- 요청 본문의 `thinkingLevel: low`와 간결한 지시문은 모의 전송 테스트로 검증했다. 격리된 로컬 웹에서 가짜 키와 임시 요청 가로채기로 대기 상태를 만들고, 스피너 하나·경과 시간 표시 제거·취소 후 단어 화면 복귀를 확인했다. 일반 설정에서 1초 주기 linear 회전, 동작 줄이기 설정에서 정지 상태를 확인했다. 검증 후 가로채기와 미디어 설정을 해제하고 새로고침해 가짜 키 메모리를 지웠다. 실제 Google 생성 호출이나 유료 요청은 하지 않았다.
- 실제 모델의 개선 전후 응답 시간과 아이디어 품질을 비교 측정하지 않았다. 설정 변경을 검증한 것이지 몇 초 빨라진다고 입증한 것은 아니다. 유효한 개인 키로 동일한 주제·단어·조건의 생성·발전·구체화를 여러 번 비교해야 한다.
- `low`에서도 사고·추론이 완전히 꺼지는 것은 아니며 아이디어 품질과 조건 준수에 차이가 생길 수 있다. 네트워크·제공업체 부하에 의한 지연은 앱에서 제거할 수 없다. Render는 정적 웹 파일을 제공하며 Gemini 요청을 중계하지 않는다.
- 스피닝 휠은 진행률이나 완료 예상 시간을 뜻하지 않는다. JSON이 끝까지 완성되고 기존 검증을 통과한 뒤에만 결과를 보여준다. 스트리밍 기능이나 자동 재시도·모드 대체를 추가하지 않았다.
