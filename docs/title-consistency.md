# 제목 스타일 통일 및 결과 화면 정리

## 적용 범위와 기준

- 웹의 모든 화면·팝업 주제목(h2): 32px / 전체 행 높이 41px / Bold 700 / 자간 -0.035em.
- Android의 화면 제목, 모델 설정·개인 키 입력 제목, 주제 선택·직접 입력 팝업 제목: 32sp / 전체 행 높이 41sp / 실제 Bold 서체 / 자간 -0.035em.
- Apple Design의 계층 기준에 맞춰 크기·굵기·행간을 하나의 공통 스타일로 관리한다. 본문·단어 카드·보관함 카드의 작은 부제목은 기존 정보 계층을 유지한다. 데스크톱 소개 영역의 마케팅 h1은 앱 화면 제목과 구분한다.
- 기존 결과 제목과 로딩 제목의 별도 CSS 크기 설정을 덮어써 화면마다 달라지지 않게 한다. Android의 Medium 서체가 제목의 Bold를 대신하던 문제를 수정한다.
- 41은 이전 요청과 동일한 모바일 디자인 논리 단위다. 웹 인쇄 단위 41pt(약 54.67px)를 의미하지 않는다.

## 탐색 변경

새로 생성한 결과와 보관함에서 연 결과 모두 상단의 `단어 조합` 버튼을 표시하지 않는다. 하단 홈 / + / 보관함은 유지한다. 내 단어 편집 화면의 단어 조합 복귀와 구체화·저장 화면의 결과 복귀는 별개 기능이므로 유지한다.

## 검증 기준

- 웹 테스트: 공통 CSS 토큰, 결과·로딩·팝업 포함 적용 범위, 결과 화면의 복귀 버튼 제거 및 내 단어 편집 복귀 유지.
- Android 계측 테스트: 홈·단어 조합·생성 결과·저장·보관함·주제 팝업·모델 설정·키 입력 화면의 실제 TextView 크기/행 높이/Bold 검사. 저장 전 생성 결과와 보관 결과 모두 불필요한 버튼이 없는지 검사.
- 기본 생성·다듬기 확인 버튼·구체화·저장·보관함 재열기 회귀 테스트는 명시적인 규칙 시연 모드에서 수행하며, 외부 AI 성공 검증으로 간주하지 않는다.
- 개인 키는 계속 메모리 전용이다. 키 인증 실패는 공통 제목 스타일 변경과 무관하며 유효한 개인 키를 사용한 실제 AI 검증은 별도다.

## 이번 변경의 실행 결과

- Node 테스트 61개 통과, 웹 프로덕션 빌드 성공.
- Android APK 빌드·에뮬레이터 설치 성공, 코어 계측 검증 13개 그룹 통과. 검증 전후 사용자 보관함 파일의 SHA-256이 동일하다.
- 브라우저에서 홈·주제 선택 팝업·생성 결과 제목의 계산된 스타일이 `32px / 41px / 700`임을 확인했다. 새 생성 결과의 `단어 조합` 버튼 수는 0이다.
- 푸시 대상 Git 인덱스 78개 파일, 기존 커밋 이력의 137개 파일 객체 및 APK 압축 해제 항목 21개에 대한 패턴 기반 비밀정보 검사에서 탐지 결과가 없었다. 모든 형태의 비밀정보 부재를 보증하는 것은 아니다.
