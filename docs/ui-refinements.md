# UI 및 저장 이름 정리

## 적용 범위

웹과 Kotlin Android 앱에 다음을 함께 반영했다.

1. 새 아이디어의 기본 저장 이름은 `새 아이디어 1`, `새 아이디어 2` 형식이다. 보관함의 현재 번호 중 최댓값 다음 값을 사용한다. 같은 아이디어를 다시 저장하면 기존 이름을 유지하고 사용자가 이름을 편집할 수도 있다. 아이디어 본문에서 AI가 작성한 원래 제목은 별도로 유지한다.
2. `오류 시 규칙 결과로 자동 대체하지 않습니다`를 `오류 시 임의 결과로 자동 대체하지 않습니다`로 교체했다. 실제로 오류를 규칙 결과로 대신하는 동작을 추가한 것이 아니다.
3. 모델 설정의 맨 아래 중복 `클라우드 연결 설정` 묶음을 삭제했다. 상단 `클라우드 AI` 선택에서 기존 개인 키 입력 화면으로 이동하며 제공업체별 비용 동의 저장 정책은 유지한다.
4. Android 주제 선택 팝업을 웹과 같은 구성으로 정리했다. 밝은 배경·둥근 흰색 카드·왼쪽 아이콘·제목 및 설명·오른쪽 화살표·닫기·취소 버튼을 사용한다.
5. 직접 입력 화면의 뒤로 가기 텍스트를 숨기고 화살표만 표시한다. 접근성 이름 `선택지로 돌아가기`와 44px/dp 터치 영역은 유지한다.
6. 보관함에서 연 아이디어 상세의 상단 `단어 조합` 이동 버튼을 제거했다. 하단 탭으로 홈과 보관함을 이동할 수 있다.
7. 다듬기 방식 버튼은 선택과 강조 표시만 한다. 선택 후 나타나는 `이 방식으로 다듬기`를 눌렀을 때만 기존 생성 경로를 호출한다. 결과 변경 또는 화면 이동 시 대기 중인 선택을 초기화한다.

## 기존 자동 검증 이름과 데이터 보호

`자동 검증 · 규칙 xxxxxx`, `직접 주제 검증 · 규칙 xxxxxx`에서 `xxxxxx`가 정확히 6자리 소문자 16진수인 이전 검증 이름만 번호형 이름으로 변환한다. 일반 사용자 이름은 바꾸지 않는다. 백업을 검증할 때도 같은 처리를 하며 반복 적용해도 이름이 계속 바뀌지 않는다.

Android 자동 검증은 앱의 실제 보관함 대신 캐시의 격리된 저장소를 사용한다. 검증 종료 후 원래 저장소·라이브러리 참조를 복원한다. 검증 전후 실제 보관함 파일의 SHA-256이 동일함을 확인했다. 기존 아이디어를 삭제하지 않는다.

## 검증

- Node 테스트 56개 통과 및 웹 빌드 성공. 기본 이름·중복 방지·재저장·기존 검증 이름 변환·일반 이름 보존·두 단계 다듬기·중복 설정 제거를 포함한다.
- Android APK 빌드 및 에뮬레이터 코어 검증 **12개 그룹 통과**. 선택만으로 작업이 시작되지 않음, 실행 버튼을 눌러야 변경됨, 기본 저장 이름 1·2, 보관함 상세의 상단 조합 버튼 제거, 텍스트 없는 접근성 뒤로 버튼, 팝업 카드의 설명과 좌우 아이콘을 포함한다.
- 웹 직접 조작: 방식 선택 후 원문 유지 → 실행 후 내용 변경, 저장 입력란의 `새 아이디어 1`, 모델 설정에 클라우드 진입이 하나만 남음을 확인했다.
- 실제 개인 키의 유료 요청은 이번 UI 점검에서 실행하지 않았다. 실제 휴대폰의 폰트·키보드·터치감은 별도 확인이 필요하다.
- 로컬 웹 및 새 APK에 반영했다. Git 원격 푸시는 수행하지 않았다.
