# 제목 행간과 Gemini 키 인증 점검

## 제목 행간

- 최초 변경 대상은 `어떤 아이디어를 만들어 볼까요?`, `뜻밖의 세 단어를 조합해 보세요.` 두 제목이었다. 후속 요청으로 모든 화면·팝업 제목에 32/41 Bold 스타일을 공통 적용했다. 최신 기준은 [제목 통일 및 결과 화면 정리](title-consistency.md)를 따른다.
- 요청의 41pt를 모바일 UI의 논리 포인트로 해석하여 웹 `41px`, Android `41sp`의 **전체 행 높이**로 적용했다. CSS 인쇄 단위 `41pt`(약 54.67px)를 의미하는 경우에는 다른 값이므로 별도 조정해야 한다.
- Android는 글꼴 크기 설정에 맞춰 sp를 변환하며 지원 기기에서는 폴백 글꼴의 추가 행간을 끈다. 후속 변경에서는 다른 제목의 크기·굵기·행간도 공통 스타일로 통일했다.

## 이번 HTTP 400과 확인 범위

- 사용자 화면은 `API_KEY_INVALID` 또는 Google의 invalid/expired 메시지를 분류했을 때만 표시되는 문구였다. 이전에 수정한 JSON MIME 열거형 오류와 구분된다.
- 앱·웹은 입력한 키를 `x-goog-api-key` 헤더로 보낸다. 환경변수, 소스에 들어 있는 공용 키, 이전 키 파일을 읽지 않는다.
- 실제 Google 엔드포인트에 명확히 가짜인 테스트 키를 보내 동일한 `API_KEY_INVALID / HTTP 400`을 재현했다. 이 검사는 사용자 키를 읽거나 사용하지 않았다.
- 정상 개인 키로 인증 또는 생성에 성공한 것은 아니다. 사용자 키가 만료·폐기·차단되었다면 앱 코드로 되살리거나 인증을 우회할 수 없다.

## 입력 경로 보완

- 기존 Gemini 입력란의 512자 제한은 긴 값을 조용히 자를 수 있었다. Gemini 입력란의 자동 잘림을 제거하고 설정 저장·요청 단계에서 8192자의 방어적 상한으로 명시적으로 검사한다. **사용자 키가 실제로 잘렸다는 의미는 아니다.**
- 앞뒤 공백·BOM·제로폭 공백을 정리한다. 키 내부의 공백/줄바꿈, 따옴표, `GEMINI_API_KEY=`, `GOOGLE_API_KEY=`, `Bearer`, 가려지거나 생략된 문자열을 전송 전에 고정 문구로 안내한다. 키 일부를 오류에 출력하지 않는다.
- Google의 invalid 응답과 expired 응답을 나눠 표시하고 알려진 `API_KEY_INVALID` 코드만 안내한다. 키 형식만으로 유효성을 판정하지 않으며 기존·신규 접두어를 제한하지 않는다.
- OpenAI 입력 정책은 변경하지 않았다. 키는 계속 메모리 전용이다.

## 새 연결 확인

개인 키 화면에서 Google Gemini를 선택하면 `Gemini 연결 확인 · 생성 없이` 버튼이 표시된다. 입력 및 전송·비용 동의를 확인한 후 사용자가 **직접 눌렀을 때만** Google의 모델 정보 조회(GET)를 실행한다. 저장 버튼은 이 요청을 자동 실행하지 않는다.

인증/모델 정보 조회 성공은 실제 생성 결과, 생성 권한 전체, 잔여 사용량·요금 상태까지 보장하지 않는다. 실패하면 생성 요청을 반복하지 말고 키 상태를 먼저 확인한다. 키/제공업체/동의 변경이나 화면 종료 시 요청을 취소하고 이전 응답을 표시하지 않는다.

## 사용자가 확인할 순서

1. [Google AI Studio 키 관리 안내](https://ai.google.dev/gemini-api/docs/api-key)에서 해당 키의 상태, Gemini API 사용 제한을 확인한다. 오래되거나 차단/폐기된 키라면 사용 가능한 키를 직접 준비한다. 앱이 키를 발급하거나 제한을 해제하지 않는다.
2. 키 목록의 이름이나 가려진 표시가 아닌 **복사 버튼으로 전체 키 값**을 복사한다.
3. 새 앱의 모델 설정 → 클라우드 AI → Google Gemini에서 다시 붙여넣고 동의한 뒤 `Gemini 연결 확인 · 생성 없이`를 누른다. API 키를 채팅이나 소스에 넣지 않는다.
4. 연결이 성공하면 설정 저장 후 아이디어를 생성한다. 연결 확인에서도 `API_KEY_INVALID`면 해당 키 인증은 아직 해결되지 않은 것이다.

## 최초 수정 당시 실행한 검증

- Node 테스트 61개 통과, 웹 빌드 성공.
- Android APK 빌드·설치 성공, 코어 검증 13개 그룹 통과. 두 제목의 실제 TextView 행 높이, 긴 테스트 키의 입력 보존, 형식 검사와 연결 확인 버튼 존재 여부를 포함한다.
- 브라우저에서 두 제목의 계산된 `line-height: 41px` 확인.
- Google 실제 엔드포인트: 의도적으로 잘못된 테스트 키의 인증 실패 재현. 생성·발전·구체화 요청 형식은 키 없는 인증 거절 단계까지 통과.
- 사용자의 유효 키로 인증·생성하는 검증은 미완료이며, Google 계정/키 상태에 대한 변경은 수행하지 않았다. Git 원격 푸시는 하지 않았다.
