# + 버튼의 주제 선택 팝업

- 적용: React 웹과 Kotlin Android 네이티브 앱. 분야를 무작위로 선택하던 흐름을 제거했다.
- + 버튼은 팝업만 연다. 기존 화면, 단어, 아이디어를 바꾸거나 모델을 호출하지 않는다.
- 첫 화면: 음식 개발, 프로그램 개발, 공모전 주제, 직접 입력의 **선택지 4개**와 취소 버튼.
- 기존 분야 버튼은 선택한 분야에서 세 단어를 뽑고 **단어 조합 화면**으로 이동한다. 주제를 고르는 것만으로 규칙 결과를 생성하거나 AI를 호출하지 않는다.
- 직접 입력 버튼은 같은 팝업 안의 입력 화면으로 전환한다. 주제 1~80자, 공백 입력은 이동 불가. `단어 조합으로 이동`을 누르면 입력한 주제의 단어 조합 화면으로 이동한다.
- 조합 화면에서 단어 고정·다시 뽑기·내 단어 추가를 사용할 수 있다. `이 조합으로 창조하기`를 눌러야 현재 설정된 방식으로 아이디어를 생성한다. 클라우드 AI도 이 버튼을 누르기 전에는 생성 요청을 보내지 않는다.
- `선택지로 돌아가기`로 왕복하는 동안에는 입력을 유지한다. 취소 후 새로 연 팝업의 입력은 초기화한다.
- 취소/닫기는 호출이나 저장 없이 기존 화면으로 돌아간다. 웹 Escape와 포커스 가두기·복귀, Android 시스템 뒤로 닫기도 지원한다.
- 기존 아이디어가 미저장 상태라면 선택 확정 후 기존 저장 확인 절차를 거친다. 단순 팝업 열기·취소에는 이 확인을 띄우지 않는다.
- 조합 화면에서 명시적으로 생성을 시작한 뒤 취소 또는 실패하면 해당 주제의 단어 조합 화면에서 재시도할 수 있다.
- 개인정보·API 키 저장 정책, Gemini 요청 수정, 홈에서 분야를 골라 조합하는 흐름은 유지한다. 팝업의 주제는 선택값이며 **단어 조합은 여전히 무작위**다.

검증 기준: Node 자동 테스트, 웹 빌드, Android APK 빌드 및 에뮬레이터 코어 검증. Android는 클라우드 모드에서 네 선택지 모두 조합 화면까지만 이동하고 오류·작업·결과가 없는지 확인한다. 이후 단어 고정·다시 뽑기를 거쳐 규칙 시연 모드에서 명시적인 생성 버튼을 눌러 선택한 단어가 결과에 사용되는지 확인한다. 공백 차단·입력 유지·취소 시 기존 아이디어 보존 검증도 유지한다. 실제 휴대폰에서의 키보드·터치감과 실제 개인 키를 이용한 유료 모델 호출은 이 UI 검증에 포함하지 않는다.

최신 실행 결과: Node 테스트 66개 및 웹 빌드 통과. 새 Android APK 빌드·설치와 에뮬레이터 코어 검증 16개 그룹 통과. 에뮬레이터 연결 중단 후 재검증 과정에서 기존 Activity 재사용으로 테스트 시작이 대기하지 않도록 검증용 시작 Intent에 CLEAR_TASK를 추가했다. 사용자 보관함은 검증 전후 SHA-256이 동일하다. 웹에서도 추천 분야 선택과 직접 입력 후 조합 화면 진입, 단어 고정·다시 뽑기, 명시적 생성 후 선택 단어 반영을 확인했다.
